# リリース試験マトリクス

## 実施上のルール
- 各ケースを `NOT_RUN / PASS / FAIL / BLOCKED` で管理する。初稿はすべて `NOT_RUN`。仕様を作成しただけでテスト済みと記載しない。
- 実施記録には `buildHash / OS API / メーカー機種 / RAM / GPU / 色モード / 入力ファイルhash / 作業者 / 日付` を添付する。
- 画像データ/顔/GPSはレポートの外部アップロードに同意がない限り添付しない。

## セキュリティ
- 非信頼画像を対象としたlibFuzzerコーパス（ライセンスを満たすもの）、HWASan / UBSan実行。
- SSL/HTTP通信監査：画像・URI・位置・metadataが許可なく送信されない。
- ローカルキャッシュ消去と再起動後の元写真再読み込みを確認。
- ライブラリnotice、データベースのCC/LGPL等の義務、SBOMとサブ依存性を確認。

## 出荷判定
- `FAIL`が残る原本保護/クラッシュ/入力安全/色管理項目はリリースを止める。
- 追加形式は機能ゲートで隠せるが、サポートされると表示した機能での色破綻はリリース不可。
- 性能目標未達は計測データと改善計画を記録し、対象端末の機能制限または実装見直しを選択する。
